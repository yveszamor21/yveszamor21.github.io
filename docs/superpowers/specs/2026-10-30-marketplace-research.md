# SafeQora marketplace research
Approved direction: user requested scan-to-product, current Amazon/Walmart offers, competition, acquisition quantity/cost, profit and demand, then said “Add them”. Preserve the GitHub app/origin, scanner, saved records and manual research.

Architecture: keep the static GitHub UI. Add an owner-private Sites Worker as research bridge, using existing hosted ChatGPT identity. Open the bridge with a public random nonce from a user-initiated button; fetch provider data same-origin after sign-in and send only normalized research back by postMessage to the exact GitHub origin. The UI validates origin, popup source, nonce and current barcode. Purchase costs and saved records stay in the GitHub browser. Provider keys live only in server secrets. No API subscriptions are purchased.

Providers: Rainforest for Amazon product/offers, BlueCart for Walmart product/offers. Unconfigured keys return explicit unavailable states; no sample/demo prices. Product lookup uses GTIN/UPC, retains candidate details, and requires human verification of size/pack/condition. Seller counts deduplicate retrieved identifiable sellers and say “at least”, never equate offers with unique sellers or claim full coverage. Surface only source-backed demand values with units and period; Walmart demand remains unavailable if provider supplies none. No sell-through prediction by dividing volume by sellers.

UI: marketplace selector, research action, two comparable cards (product, price+shipping, identified sellers, demand, source/time/status), apply selected price into existing calculator without marking match, fees or eligibility verified. Add four independent fulfillment cost estimates and side-by-side profit, quantity totals, ROI, margin and break-even using existing validated calculator. Unknown fees block BUY. Stale async results cannot replace a new product. Product/price/quantity edits invalidate snapshots. Existing storage keys stay intact.

Alternatives: direct browser calls expose keys and run into CORS; excluded. Rehosting the whole app would change origin and separate existing browser data; excluded. The private popup bridge preserves the origin and uses hosted authentication without putting secrets in the frontend. One click after scan is needed because browsers block asynchronous popups; no deceptive automatic fetch claim.
